# ADR-004. Аварийное переключение

## Контекст и требования

Система должна восстанавливаться после отказа экземпляра, зоны и региона. Нельзя активировать две записи одной поездки или повторить выплату. Требование 99,99% проверяется по пользовательским сценариям, а не по доступности отдельных контейнеров.

## Решение

Внутри региона переключение автоматическое. Межрегиональное переключение выполняет резервируемая автоматика после проверки данных и блокировки старой записи. Если безопасность переключения не подтверждена, требуется решение SRE.

### Порядок передачи региона

1. Подтвердить отказ и прекратить направлять новые операции на площадку.
2. Заблокировать старую запись, включая фоновые обработчики. Одной смены маршрута недостаточно.
3. Проверить актуальность и допустимость использования резервных данных, активировать БД и обработку Kafka.
4. После проверки готовности переключить трафик. Повторы используют прежние ID, неизвестные платежи сверяются с провайдером.

Одновременно пишет только один владелец. Если старую запись нельзя гарантированно заблокировать, новая не запускается. Возврат в восстановленный регион выполняется планово после синхронизации.

### Сценарии отказа

| Отказ | Обнаружение | Действие |
| --- | --- | --- |
| Экземпляр сервиса или узел | Readiness и метрики Kubernetes | Исключить экземпляр, обслуживать оставшимися репликами, восстановить емкость |
| Зона доступности | Проверки регионального входа и хранилищ | Использовать живые зоны, HA-переключение PostgreSQL, перевыбор лидеров Kafka |
| Primary PostgreSQL | Проверки HA-кластера PostgreSQL | Исключить старый primary, переключить на актуальный синхронный резерв, переподключить сервисы |
| Брокер Kafka | Ошибки публикации, ISR и consumer lag | Перевыбрать лидеров из синхронизированных реплик. При недостатке реплик не подтверждать запись, сохранять outbox |
| Регион целиком | Внешние проверки и региональные метрики | Передать его данные парной площадке по процедуре выше |
| Межрегиональная сеть | Рост лага и потеря связи | Не включать второго владельца только из-за отсутствия связи. Переключение возможно после блокировки старой записи |

## Компромиссы

Подготовленный резерв дороже восстановления из копий, но сокращает простой. Возможное отставание данных и ограничения передачи между странами учитываются до переключения.
