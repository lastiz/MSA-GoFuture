# ADR-004. Мониторинг событийной платформы

## Контекст

Процессы могут быть доступны, пока события не обрабатываются, Saga ожидает ответ, а динамическая цена использует старые данные. Проверки доступности контейнера недостаточно.

## Требования

Определить подход, метрики и инструменты мониторинга. Отразить инструменты на [C2 событийной платформы](C2-event-platform.puml). Сохранить базовую доступность 99,95% из задания 1 и покрытие всех критических сценариев метриками и алертами.

В глобальном развертывании задания 3 правила SLO для критических сценариев усиливаются до 99,99%, инструменты мониторинга сохраняются.

## Решение

Наблюдаем четыре уровня: API, событийную платформу, Saga и бизнес-результаты. Метрики показывают деградацию, логи и трассировки помогают найти причину. Дашборды разделяются по региону и сервису, доступность проверяется на пользовательских сценариях.

### Инструменты

| Инструмент | Назначение и обоснование |
| --- | --- |
| Prometheus | Уже используется. Собирает метрики сервисов, обработчиков outbox, Flink и инфраструктуры, вычисляет правила алертов |
| Kafka Exporter, JMX Exporter, PostgreSQL Exporter | Consumer lag, состояние брокеров и БД. JMX Exporter работает при процессах JVM, PostgreSQL Exporter у каждой БД |
| Grafana | Существующий интерфейс метрик и логов. Трассировки открываются отдельно в Jaeger UI по trace_id |
| Loki | Сохраняем существующее хранилище структурированных логов |
| OpenTelemetry SDK и Collector | Связывают обработку запросов и сообщений, передают логи в Loki и трассировки в Jaeger по OTLP |
| Jaeger | Принимает трассировки и позволяет исследовать путь обработки события в Jaeger UI |
| Elasticsearch для Jaeger | Постоянное хранилище трассировок, отдельное от геоиндекса Geography |
| Alertmanager | Группировка и маршрутизация алертов SRE и владельцам доменов, подавление повторных уведомлений |

На C2 сбор телеметрии показан на примере Booking и применяется ко всем сервисам. Повторяющиеся связи и физическое хранилище Jaeger опущены для читаемости.

### Метрики и реакция

Пороги задержек и длительности шагов согласуются по результатам нагрузочных тестов. Алерты направляются SRE и владельцу домена с указанием региона и причины.

| Область | Метрики | Реакция |
| --- | --- | --- |
| API | Частота запросов, технические ошибки, p95/p99 задержки, доступность | Угроза SLO 99,95%, бизнес-отказы учитываются отдельно |
| Kafka | Скорость публикации и чтения, consumer lag, возраст необработанных событий | Рост задержки или остановка обработки |
| Брокеры | Недоступные и недореплицированные партиции, ISR, свободный диск | Потеря доступности или запаса реплик и ресурсов |
| Outbox | Число и возраст неопубликованных записей, ошибки отправки | Накопление сообщений без прогресса публикации |
| Потребители | Время обработки, ошибки контрактов, повторы, retry backlog, размер и возраст DLQ | Финансовый DLQ требует немедленного разбора, остальные - по росту и возрасту |
| Saga | Процессы по состояниям, длительность шагов, ожидающие компенсации | Превышение срока шага или компенсации, не длительность самой поездки |
| Flink | Backpressure, задержка обработки по времени события, ошибки checkpoints, перезапуски | Остановка сигналов или невозможность сохранять состояние |
| Цена и подбор | Возраст сигналов, свежесть координат, время назначения, распределение водителей | Устаревшие данные или ухудшение подбора |
| Деньги | Успешность оплат и выплат, неизвестные результаты, задержка начислений, расхождения при сверке | Денежные расхождения требуют немедленного разбора |
| Нагрузка | Активные поездки, события/с, CPU, память, соединения и блокировки БД | Контроль емкости более 500 000 поездок и необходимости масштабирования |
| Наблюдаемость | Доступность источников, ошибки Collector, Loki, Jaeger и хранилища | Потеря телеметрии также вызывает алерт |

### Логи и трассировки

Структурированные логи содержат время, сервис, регион, партнера, результат и идентификаторы события, Saga и трассировки. Контекст OpenTelemetry передается через HTTP и Kafka. Секреты и персональные данные не записываются. Идентификаторы операций используются для поиска, а не как метки Prometheus. В задании 4 метка партнера допускается только для ограниченного набора агрегатов с контролем числа временных рядов. Трассировка не заменяет финансовый аудит.

## Альтернативы и компромиссы

Сохраняем существующие метрики и логи, добавляем Jaeger для трассировки. Альтернатива - Tempo с просмотром в Grafana. Компромисс Jaeger - отдельный интерфейс и хранилище. Объем телеметрии ограничивается сроком хранения, выборкой трассировок и числом меток.
